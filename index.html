PROBLEM

왜 북켓몬인가? 도서 추천의 한계점

콜드 스타트 문제 (Cold Start)

신규 사용자 또는 비로그인 방문객의 정보 부족으로 초기 매칭 신뢰도 급락 및 이탈율 심화 현상이 발생합니다.

사용자 관심사 수렴의 심각한 지연

성향을 포착하고 고도화 분석 모델을 태우는 데 복잡하고 느린 연산 주기가 요구되어 고질적인 랙이 유발됩니다.

시스템 물리적 제한 요소

게스트 슬롯 제한 최대 3 Rooms
세션별 대화 수 한계 단 15 Turns 이내

극도로 제한된 자원 하에서, 극도로 빠른 큐레이션 수렴 성과가 강력히 요구됩니다.

PIPELINE

3대 핵심 기술 모듈의 유기적 융합

STAGE 1

정보 검색 (Retrieval)

Qdrant 벡터 데이터베이스와 고도화 KURE 임베딩 파이프라인을 연계해 사용자 맥락과 의미론적 정합성이 1차 필터링된 대규모 도서 후보군을 실시간 추출합니다.

STAGE 2

개인화 랭킹 (Ranking)

LightFM 협업 필터링 엔진과 유저 실시간 수치 프로필 룰 조합을 8:2 비율로 혼합 적용하여, 사용자 성향 맞춤 최상위 인덱스를 즉시 정밀 계측 정렬해냅니다.

STAGE 3

생성형 설명 (Reasoning)

실시간 추론 Nemotron 모델과 페르소나 템플릿 메타 구조를 이용해, 왜 해당 도서가 사용자 취향에 부합하는지 딥 큐레이션 사유를 완벽한 단락으로 즉석 생성합니다.

BOOKMON 전체 아키텍처 토폴로지
ARCHITECTURE

북켓몬 분산 시스템 구조도

Frontend React

대화형 슬롯 UI, 다이어그램, 큐레이션 결과 리포트를 부드러운 상태 기반 인터랙션 및 프레임워크 최적 렌더링으로 지연 없이 노출합니다.

Backend Gateway Spring Boot

비즈니스 도메인 서비스 가동, Redis 세션 풀 연동 분산 게스트 트래픽 보호 및 API 트랜잭션 오케스트레이션을 완벽 지휘합니다.

AI Core Engine FastAPI

경량화 비동기 백엔드 구조로 LightFM 모델 추론 및 사용자 임베딩 유닛 바인딩 연산을 단자릿수 ms 내에 전담 수행합니다.

Vector Database Qdrant

다차원 도서 인덱스를 HNSW 그래프 색인 처리하여 실시간 벡터 세그먼트 매칭 쿼리를 분당 수만 회 이상 소화 가능하도록 지원합니다.

Reranker Service GTE GPU Server

정밀 다언어 리랭킹 GTE 모델을 로드하여 단순 거리 기반 조회의 세밀한 정합 한계를 딥러닝 어텐션 보정으로 완벽히 메꿔줍니다.

Cache Storage Valkey / Redis

중복 검색 임베딩 및 단기 연산 랭킹 테이블을 초고속 인메모리 룩업으로 처리하여 GPU 파이프라인의 극단 지연을 제거합니다.
