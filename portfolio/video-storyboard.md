# 북켓몬(Bookemon) 홍보영상 구성안

> **형식** : HTML 애니메이션 + 보이스오버 | **목표 길이** : 3분 30초~4분 | **대상** : 팀/학교 발표
>
> **핵심 축** : AI 추천 파이프라인 × 시스템 아키텍처 완성도

---

## 전체 흐름 요약

| # | 구간 | 키워드 | 시간 |
|---|------|--------|------|
| 1 | PainPoint | "좋은 책인데… 왜 안 돌아오지?" | 0:00 – 0:30 |
| 2 | Needs | 추천 정확도 + 재방문 동기, 둘 다 필요 | 0:30 – 0:55 |
| 3 | Why? | 기존 접근법의 한계 | 0:55 – 1:20 |
| 4 | What? | 북켓몬이 설계한 답 | 1:20 – 1:50 |
| 5 | How | 아키텍처 & 파이프라인 전개 | 1:50 – 3:00 |
| 6 | Solution | 성능 수치 + 데모 + 마무리 | 3:00 – 3:30~4:00 |

---

## Scene-by-Scene 스크립트 & 화면 연출

---

### SCENE 1 — PainPoint (0:00 – 0:30)

#### 보이스오버
> "여러분은 책을 추천받아 봤나요?  
> 맞아요. 좋은 책이었어요. 하지만… 다음날 그 앱에 다시 돌아갔나요?"

#### 화면 연출
- **오프닝 타이포** : 검정 배경에 흰 글씨 한 줄씩 등장
  - "추천 받았다"
  - "읽었다"
  - "그리고 — 떠났다"
- 화면 전환: 도서 추천 앱 인터페이스 목업 (페이지 스크롤 후 앱 종료 애니메이션)
- 강조 수치: **"기존 도서 추천 서비스의 평균 재방문율은 낮다"** (텍스트 페이드인)

#### 핵심 메시지
> 추천 정확도를 올려도 재방문율은 비선형으로 반응한다.

---

### SCENE 2 — Needs (0:30 – 0:55)

#### 보이스오버
> "사용자에게는 두 가지가 필요합니다.  
> 지금 이 순간 나에게 맞는 책 — 그리고, 내일 다시 올 이유."

#### 화면 연출
- 화면 2분할 슬라이드
  - **좌측** : 돋보기 아이콘 + "개인화 추천 정확도"
  - **우측** : 루프 화살표 아이콘 + "재방문 동기"
- 두 원이 서로 맞물리는 벤다이어그램 애니메이션으로 수렴
- 중앙 교집합에 **"북켓몬"** 로고 등장

#### 핵심 메시지
> 이 두 목표는 독립적으로 설계되어야 하며, 동시에 유기적으로 연결되어야 한다.

---

### SCENE 3 — Why? (0:55 – 1:20)

#### 보이스오버
> "기존 서비스들은 추천 엔진 하나로 두 문제를 동시에 풀려고 했습니다.  
> 그 결과는 — 둘 다 어중간했습니다."

#### 화면 연출
- **기존 방식 비교 카드** 3장 순차 등장:
  1. 단순 벡터 검색 → "정확하지만 단조롭다"
  2. 인기도 기반 추천 → "안전하지만 개인화 없음"
  3. 별도의 보상 시스템 → "추천과 연결이 끊김"
- 각 카드에 ❌ 표시가 등장하며 밀려남
- 배경 색상: 회색 계열 (문제 상황 = 무채색)

#### 핵심 메시지
> 단일 목표 최적화로는 이탈을 막을 수 없다.

---

### SCENE 4 — What? (1:20 – 1:50)

#### 보이스오버
> "북켓몬은 세 가지 목표를 동시에 최적화하는 추천 파이프라인을 설계했습니다.  
> 그리고, 모든 독서 행동을 캐릭터 성장으로 연결했습니다."

#### 화면 연출
- **수식 등장 애니메이션**:
  ```
  final_score = w₁ × S_personal + w₂ × S_pop + w₃ × S_recency
  ```
  - 한 줄씩 타이핑 효과로 등장
  - 각 항목에 색상 강조 (S_personal=파랑, S_pop=초록, S_recency=주황)

- **화면 분할 전환**:
  - 좌측: 수식 → "AI 파이프라인"
  - 우측: 북켓몬 캐릭터 진화 다이어그램 → "게이미피케이션"
  - 하단: 연결 화살표 "독서 행동 → XP → 진화"

#### 핵심 메시지
> 기획 의도가 수식으로 인코딩된다 — 기획자와 엔지니어가 같은 언어로 소통한다.

---

### SCENE 5 — How (1:50 – 3:00)

> 이 구간이 영상의 기술적 핵심. 3개 서브씬으로 분리.

---

#### SCENE 5-A : 시스템 아키텍처 (1:50 – 2:15)

##### 보이스오버
> "전체 시스템은 Spring Boot 게이트웨이, FastAPI AI 서버, 그리고 3개의 데이터 레이어로 구성됩니다.  
> ML 모델 교체 시 백엔드 변경 없이 AI 서버만 롤링 업데이트할 수 있도록 레이어를 분리했습니다."

##### 화면 연출
- 아키텍처 다이어그램 레이어별 순차 등장 (좌→우, 위→아래 fade-in)
  - Client → Spring Boot → FastAPI → (PostgreSQL / Qdrant / Redis)
- 각 레이어 등장 시 해당 기술 뱃지 (React, Java, Python, Qdrant 등) 스파크처럼 표시
- 강조: **"100,000건 도서 벡터 · 17개 테이블 · 36개 API"** 카운터 애니메이션

---

#### SCENE 5-B : 추천 파이프라인 시퀀스 (2:15 – 2:40)

##### 보이스오버
> "사용자가 자연어로 질문하면 — HyperCLOVA X가 의도를 분석하고,  
> Qdrant에서 Top-50 후보를 꺼내 3단계 리랭킹을 거쳐 Top-3를 추천합니다.  
> 콜드스타트 유저와 기존 유저는 가중치가 동적으로 전환됩니다."

##### 화면 연출
- 시퀀스 다이어그램 애니메이션 (단계별 화살표 순차 등장)
  1. 사용자 입력 → 쿼리 정제 (HCX)
  2. Qdrant Top-50 검색
  3. S_personal × S_pop × S_recency 계산
  4. LLM 배치 리랭킹 → Top-3 선정
- 분기 표시: **"신규 유저 w₁=0.1 / 기존 유저 w₁=0.5"** 동적 전환 애니메이션
- 화면 하단: **"추천 응답 목표 ≤ 5초"** 타이머 이펙트

---

#### SCENE 5-C : 게이미피케이션 + 평가 설계 (2:40 – 3:00)

##### 보이스오버
> "독서대 등록, 리뷰 작성, 뽑기 — 모든 행동이 XP로 전환되고 북켓몬이 진화합니다.  
> 실제 유저 데이터 없이도, 합성 페르소나 100명으로 정량 평가를 설계했습니다."

##### 화면 연출
- XP 적립 구조 표 간략 버전 (3줄: 등록 +100 / 리뷰 +50 / 뽑기 +20) 리스트 애니메이션
- 진화 분기 트리 축약 버전 (Stage 0 → 1 → 2A/2B/2C) 순차 등장
- 전환: "합성 페르소나 100명 생성 → LightFM 학습 → 평가 지표" 파이프라인 미니 다이어그램

---

### SCENE 6 — Solution (3:00 – 3:30~4:00)

#### 보이스오버
> "북켓몬은 단순한 추천 시스템이 아닙니다.  
> 기획 의도를 수식으로, 수식을 코드로 — 그리고 코드를 경험으로 바꾸는 파이프라인입니다."

#### 화면 연출
- **성능 수치 카드** 순차 등장 (실제 측정값으로 대체 필요):
  - `Precision@5 : X.XX`
  - `NDCG@10 : X.XX`
  - `HitRate@5 : X.XX`
  - `LLM Judge 평균 : XX / 100`
  - *(페르소나 100명 기준)*
- 중앙 정렬 타이포그래피 마무리:
  - **"추천 정확도 + 재방문 동기"**
  - **"두 문제를 하나의 시스템으로"**
- 로고 + 기술 스택 한 줄 요약 등장
  - `React · Spring Boot · FastAPI · PostgreSQL · Qdrant · HyperCLOVA X`
- 팀명 / 발표일 크레딧 페이드아웃

## 화면 연출 전체 원칙

| 항목 | 가이드 |
|------|--------|
| **배경** | 문제 구간(1~3): 어두운 계열 / 해결 구간(4~6): 밝은 계열로 전환 |
| **폰트** | 타이틀: Bold 산세리프 / 보조 설명: Regular |
| **애니메이션** | 화면 전환 기본: fade + slide / 수식: 타이핑 이펙트 / 다이어그램: 단계별 드로우인 |
| **색상 강조** | S_personal=파랑 / S_pop=초록 / S_recency=주황 / XP/게이미피케이션=보라 |
| **수치** | 카운터 애니메이션 (0 → 최종값) |
| **내레이션 싱크** | 각 씬의 보이스오버 문장이 끝날 때 다음 화면 요소 등장 |

## 보완이 필요한 항목 (제작 전 확인 필요)

| 항목 | 현재 상태 | 필요한 것 |
|------|-----------|-----------|
| **실제 성능 수치** | 파일에 라벨 데이터 있음 | NDCG, Precision 최종 집계값 확인 |
| **북켓몬 캐릭터 이미지** | 진화 구조 문서만 있음 | 실제 캐릭터 시각화 자료 필요 |
| **실제 서비스 데모 화면** | 포트폴리오 HTML 있음 | 스크린샷 또는 녹화본 |
| **팀 정보** | 없음 | 팀명, 발표일, 크레딧 |
| **배경음악** | 없음 | 무음 or 저작권 프리 BGM |
