```
현재: exp(+0.001 · days)  → 오래될수록 점수 상승 (의도 반대)
수정: exp(−0.001 · days)  → 최신일수록 점수 높음 (지수 감쇠)
```
- 위치: Section 4 추천 수식, POST /chat 시퀀스 다이어그램 Note, 가챠 플로우 다이어그램

## 카테고리 B — 미구현·근거 없는 수치 (삭제 또는 출처 명시)

### B-1. Redis 응답 시간 수치
- 현재 표기: `~120ms` (캐시 HIT), `~1.8s` (캐시 MISS), `~4.2s` (Redis 장애 Fallback)
- 코드·문서 어디에도 근거 없음. 실측값도 벤치마크 기록도 없음.
- 조치: 전부 삭제하거나 "목표 응답 시간 (미실측)" 으로 명시.

---

### B-2. Redis TTL 6h — 설계 의도이지 구현값 아님
- 현재 표기: `gacha_candidates TTL = 6h`, `SETEX(key, 21600)`
- 실제 코드(`apps/ai-server/app/core/config.py`): 캐시 TTL 전부 **600초(10분)** 또는 900초.
- 21600초(6h) 값은 코드 어디에도 없음.
- 조치: 실제 구현된 TTL(600s)로 교체하거나 "설계 목표값" 임을 명시.

---

### B-3. 행동 신호 가중치 수치 — 출처 불명
- 현재 표기: 독서 중 2.0, 완독 3.0, 리뷰 5★ 3.5, 대출 조회 0.5 등
- `research-paln.md`에 신호 항목만 있고 수치 없음. HTML의 수치는 코드·문서 어디에도 없음.
- 조치: 수치 출처를 명시하거나 삭제. 설계 의도라면 "(설계값, 미구현)" 표기.

---

### B-4. Reranker 수식 단순화 — 실제 코드와 불일치
- 현재 표기: `S_personal = 0.5·vector + 0.3·genre + 0.2·history` (3항)
- 실제 코드(`profile_reranker.py`): `QUERY_FIRST / HYBRID / PROFILE_FIRST` 3개 프리셋, 각 10개 이상 가중치 항목.
  - 예시 (QUERY_FIRST): semantic 0.74, genre 0.05, purpose 0.04, preferred_book 0.05, reading_book 0.03, review_positive 0.04, disliked_penalty 0.12, audience_penalty 0.28 등
- 조치: "설계 개념 수식 (실제 구현은 3-프리셋 구조)" 임을 명시하거나, 실제 프리셋 구조로 교체.

---

### B-5. `admin/` 수동 가중치 튜닝 콘솔
- 현재 Monorepo 구조에 `admin/ # 운영 콘솔 · 수동 가중치 튜닝` 표기.
- 원본 Monorepo 명세에 없는 항목. 구현 여부 불명확.
- 조치: 구현되지 않았으면 삭제.

## 카테고리 D — 표현 과장 (수준 조정)

### D-1. "White Paper" 명칭
- White Paper는 기업·연구기관의 공식 발행 문서. AI 북 큐레이션 서비스의 기획 포트폴리오에는 과한 표현.
- 조치: "프로덕트 기획 포트폴리오" 또는 "서비스 설계 문서"로 교체.

### D-2. "기존 RecSys 문헌은 정확도(Precision)를 최적화한다"
- 학술 문헌 전체를 일반화하는 주장. 실제 RecSys 연구는 다양한 목표 함수를 다룸.
- 조치: "일반적인 추천 서비스는 클릭률·정확도 중심으로 설계되는 경우가 많다" 수준으로 완화.

### D-3. "4-홉 → 2-홉 협업 번역" 프레임
- 기획자가 수식을 직접 설계한 것은 실질적 강점이지만, 홉 수로 효과를 정량화한 근거가 없음.
- 조치: 추상적 수치 대신 구체적 사례 (어떤 스펙 협의가 줄었는지) 로 대체하면 설득력 높아짐.

### D-4. "추천 → 행동 → 학습 데이터의 순환 루프"
- `is_training_data` 플래그는 존재하지만, 리뷰 데이터를 모델 재학습에 활용하는 파이프라인이 실제로 구현되어 있지 않으면 비약.
- 조치: 구현 여부 확인. 미구현이면 "설계 목표" 또는 "향후 과제"로 표기.

## 카테고리 E — 구조·가독성 문제 (개선 권장)

### E-1. 섹션 간 수치 불일치
- 같은 항목(친구 수락 XP, 행동 가중치 등)이 섹션마다 다른 값으로 표기됨.
- 조치: 원본 명세를 단일 소스로 삼아 문서 전체를 통일.

### E-2. 기술 깊이 편차
- Vision 섹션: 추상적 서사 수준 / Architecture 섹션: 구현 파일명 나열.
- A(엔지니어) 타겟이라면 전체 섹션을 동일한 기술 깊이로 맞출 것.
- Vision도 "왜 이 설계 결정을 내렸는가"를 구체적 트레이드오프로 설명해야 함.

### E-3. Evaluation 섹션 미완성
- "Five research questions, seven offline metrics, twelve synthetic personas" 예고 후 실제 내용 없음.
- 조치: 내용을 채우거나(`evaluation.md` 내용 활용) 섹션 자체를 제거.

### E-4. 콜드스타트 전환 조건 논리 표기 불일치
- `profiler.py` 설명: `대화 ≥ 20 OR 등록 책 ≥ 3` (개인화 전환 조건)
- 동적 가중치 테이블: `대화 < 20 AND 등록 책 < 3` (Cold-start 유지 조건)
- 두 조건이 논리적으로 대칭이 아님. AND/OR 기준을 명확히 정의하고 문서 전체 일관 적용.
