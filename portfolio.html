2-Stage Retrieve → Rerank

Reranker를 파이프라인에 분리 운영한 이유

Stage 1 · Bi-encoder (빠름)

KURE Embedding으로 Qdrant Top-50을 빠르게 추출합니다. 벡터 내적만으로 계산하므로 대규모 코퍼스에서도 레이턴시를 낮게 유지합니다.

Stage 2 · Cross-encoder Rerank (정밀)

GTE Reranker(검색 결과를 다시 정밀 정렬) 전용 서버에서 쿼리-문서 쌍의 전체 문맥을 비교합니다. Cross-encoder(질문·문서를 함께 넣어 정밀 채점) 방식이라 bi-encoder보다 정밀하지만, 후보를 좁힌 뒤에만 적용해 비용을 제어합니다.

설계 근거 — 2-stage retrieve→rerank는 속도와 정확도 트레이드오프를 레이어로 분리하는 표준 구조입니다. Nogueira & Cho, Passage Re-ranking with BERT (2019) [논문]에서 정립됐고, GTE Reranker(BAAI FlagEmbedding 계열)는 production RAG(검색해서 그 내용으로 답하는 구조) 환경의 표준 컴포넌트입니다. HCX 배치 리랭킹과 병행해 최종 Top-3을 결정합니다.

What it does

핵심 기능

추천 파이프라인, 콜드스타트(데이터 없는 신규 유저 추천 문제) 전환, 게이미피케이션 리텐션을 하나의 제품으로 묶었습니다.

🎯

다중 목표 추천 — 추천을 최적화 문제로 재정의

final_score = w₁·S_personal + w₂·S_pop + w₃·S_recency 수식으로 개인화·대중성·신간 선호를 합산합니다. 추천을 단일 목표가 아니라 다중 목표 최적화(여러 기준을 동시에 맞추는 최적화) 문제로 재정의했습니다. 수식이 곧 구현 스펙이 되어 reranker.py에 직결됩니다.

🌡️

콜드스타트 동적 가중치 + Nemotron 시드

신규 유저(대화<20 AND 책<3)는 cold 가중치(personal 0.1·pop 0.7·recency 0.2)로 대중성 위주 안전 추천을 제공합니다. NVIDIA Nemotron 한국인 합성 페르소나 100만 건(CC-BY-4.0)을 콜드스타트 시드와 LightFM(추천용 하이브리드 모델) 시뮬 평가에 활용해 실 유저 없는 환경에서 평가를 완료했습니다.

🔬

18쿼리 ablation 하네스 — eval 설계 역량

Q001~Q018(장르·독서목적·오디언스·부정선호 커버) 쿼리에 0/1/2점 인간 채점 기준을 확립하고 신호별 점수 컬럼을 분리했습니다. 버그 발견(오디언스 미스매치) → 신호 보강 → 정량 개선의 측정 루프를 직접 운영한 케이스입니다.

📊

LightFM 후보 압축

1,109 유저·7:2:1 분할 LightFM 개인화 모델로 Qdrant Top-50을 Top-20으로 압축했습니다. 긍정 선호 포착율 90.52%·비선호 노출 1.45% (test 기준) [실측]. LightFM val 46.84% · test 29.15% — val/test 간 gap도 정직하게 병기합니다.

🎮

게이미피케이션 리텐션

독서 기록(XP)·레벨업·진화 연출로 재방문 유인을 설계. SELECT FOR UPDATE 행 수준 잠금으로 XP 동시성 Lost Update 방지, 진화 단계 역행 금지 불변식 구현.

📚

도서관 대출 연동

도서관정보나루(data4library.kr) 실시간 연동으로 추천 도서의 실제 대출 가능 여부를 즉시 확인. 추천이 실행 가능한 행동으로 연결됩니다.

Engineering Deep-Dive

3가지 핵심 설계 결정

기획 의도를 수치로 확정하고 설계 유효성을 데이터로 증명한 과정을 기록합니다.

01

추천 수식 직접 설계 — 다목표 최적화 재정의 reranker.py · 수식→스펙

🤔 왜

기획 의도를 모호한 언어로 전달하면 구현 오차가 생긴다. "개인화 위주"는 엔지니어마다 해석이 다르다. 추천을 다중 목표 최적화(S_personal·S_pop·S_recency 가중합)로 명시화해야 스펙이 구현에 직결된다.

✓ 어떻게

final_score = w₁·S_personal + w₂·S_pop + w₃·S_recency로 명시화. S_personal은 벡터·장르선호·행동이력을 0.5/0.3/0.2로 합산. 수식이 곧 구현 스펙이 되어 재협의 없이 코드에 직결됐다.

02

콜드스타트 동적 가중치 전환 cold/warm · LightFM · Nemotron 시드

🤔 왜

취향 데이터 없는 신규 유저에게 개인화 벡터를 바로 적용하면 첫인상 품질이 급락한다. 콜드스타트 시드 없이는 모델이 무작위에 가깝게 추천한다. 실 유저 없는 평가 환경이라 시뮬 데이터가 필요했다.

✓ 어떻게

신규(대화<20 AND 책<3): cold 가중치(personal 0.1·pop 0.7·recency 0.2)로 대중성 위주 추천. NVIDIA Nemotron 한국인 합성 페르소나(CC-BY-4.0, 100만 건)를 콜드스타트 시드·LightFM 시뮬 평가에 활용. 데이터 누적 후 warm(0.5·0.3·0.2)으로 전환.

03

18쿼리 ablation 하네스 — eval 설계 역량 Q001~Q018 · 인간 채점 · 0/1/2점

🤔 왜

데이터 없는 설계 주장은 증명이 아니다. dense 벡터 단독 검색은 오디언스 미스매치(성인 의도에 어린이 도서 노출)를 막지 못한다. Ablation(요소를 하나씩 빼보며 효과 확인) 하네스 없이는 신호 추가의 인과 기여를 분리할 수 없다.

✓ 어떻게

Q001~Q018(장르·독서목적·오디언스·부정선호 커버), 0/1/2점 인간 채점 기준 확립, 신호별 점수 컬럼 분리 → 버그 발견(오디언스 미스매치) → 신호 보강 → 정량 개선. 룰 ON/OFF ablation으로 Top-5 Precision Δ+13.34%p·Bad Rate Δ−13.34%p 입증 [성능평가 §4].

final_score = w₁ · S_personal + w₂ · S_pop + w₃ · S_recency
S_personal = 0.5·vector_sim + 0.3·genre_pref + 0.2·behavior_hist
S_pop = log_normalize(library_checkout_count) # data4library.kr 대출통계
S_recency = exp_decay(publish_date) # 지수 감쇠
Cold: (w₁=0.1, w₂=0.7, w₃=0.2) → Warm: (w₁=0.5, w₂=0.3, w₃=0.2) # 대화≥20 OR 책≥3 시 전환
추천 = 다중 목표 최적화 — 개인화·대중성·신간 선호를 가중합으로 명시화해 기획 의도와 구현 스펙을 1:1로 연결.
Retrieve-and-Rerank · 임베딩 벤치 = 평가 관점

2-stage retrieve→rerank(bi-encoder→cross-encoder)와 임베딩 벤치(KURE vs CLOVA Precision@50)는 모두 평가 관점에서 선택을 측정한 사례입니다. RAG를 만든 것이 아니라, RAG의 어느 레이어가 품질에 기여하는지를 실험으로 분리한 접근입니다. Agentic RAG·평가 설계 방향과 직결됩니다.

System Design

아키텍처 & 데이터 흐름

질의에서 최종 추천까지 레이어별 역할을 분리해, ML 모델 교체 시 무중단 롤링 업데이트가 가능한 구조를 설계했습니다.

GTE Reranker 전용 서버 분리 운영

HCX 배치 리랭킹(0~100 스코어 + 사유 생성) 외에 gte-reranker-server를 별도 서버로 분리 운영합니다. ML 모델을 교체할 때 Spring Boot 백엔드는 건드리지 않고 AI 서버만 롤링 업데이트합니다. 레이어 분리 설계의 일부입니다.

✓

"eval 설계 역량" 증명 — 18쿼리 ablation 하네스

Q001~Q018 인간 채점 하네스를 설계하고 버그(오디언스 미스매치) 발견 → 신호 보강 → 정량 개선 루프를 직접 운영했습니다. 추천을 만든 것이 아니라 eval 루프를 운영한 케이스입니다. 동일 방법론을 게임 도메인 LLM 벤치마크 설계에 적용할 수 있습니다.

✓

레이어 분리로 무중단 롤링 업데이트 구조

Spring Boot(비즈니스)↔FastAPI(AI) 분리로 ML 모델 교체 시 백엔드 변경 없이 AI 서버만 롤링 업데이트합니다. SELECT FOR UPDATE 행 수준 잠금으로 XP 동시성 Lost Update를 방지하고, 진화 단계 역행 금지 불변식을 구현했습니다.

✓

소셜 매칭 복잡도 개선 · RDB 17테이블 설계

소셜 매칭 복잡도를 O(N²)에서 O(N×K)로 개선했습니다(Qdrant Top-K 활용). RDB 17개 테이블 설계(사용자·XP·도서·상호작용 스키마)를 주도했습니다. 도서 벡터 약 10만 건(1,024차원 Cosine) [실측 | 프로젝트 명세].

Retrospective

한계 & 다음 단계

오프라인 평가로 측정한 것과 측정하지 못한 것을 솔직하게 기록합니다.

행동·개인화 신호 효과 — 제한적 측정

룰 ablation에서 행동·개인화 신호(리뷰·서재·audience) 효과는 "프로필 제외 평가" 구조상 제한적으로 측정됐습니다. 행동 신호 효과를 검증하려면 실제 유저 로그 기반 온라인 평가가 필요합니다.

→ 온라인 A/B 테스트 인프라 구성 → 룰·가중치 실시간 검증 루프 필요

LightFM 오프라인 근사 — 실서비스 루프와 차이 존재 · val/test 간 gap

LightFM candidate-eval은 Qdrant 호출 없는 오프라인 근사(50개 채점) 기준입니다. val 46.84% · test 29.15% — 두 수치를 함께 보고하며, 실서비스 추천 루프와 완전히 동일한 환경 평가는 미완입니다.

→ Qdrant 연동 온라인 평가 루프 구성 필요

최적 조합 Precision 100%·Bad Rate 0% — 오프라인 특정 구성 결과, 캡션 유지

성능평가 §9 최적 조합(llm_search_query × dense × current) Top-5 결과는 오프라인 특정 구성 평가 기준입니다. 모든 조합·실서비스 환경에서의 성능을 단정하지 않으며, 이 캡션은 정직성 원칙에 따라 유지합니다.

→ 다양한 조합·실서비스 조건에서 추가 검증 필요

RAGAS(RAG 평가 프레임워크) — 다음 단계 / 미구현 정직 표기

현재 평가는 인간 채점 기반 질의-추천 적합성 중심입니다. RAGAS(Es et al., arXiv:2309.15217, 2023)의 faithfulness·answer_relevancy·context_recall 지표는 미측정입니다. HCX 리랭킹 단계의 hallucinate 여부를 정량화하는 데 적합하지만, 현재 미구현 상태입니다.

→ 향후 온라인 A/B 테스트와 병행해 RAGAS 기반 retrieval 품질 평가 적용 계획
