## 2. 레이어별 역할

### 2-1. Client Layer

|컴포넌트|역할|
|---|---|
|Web / Mobile App|사용자 채팅 UI, 독서대, 뽑기, 소셜, 공유카드 화면. JWT를 Authorization 헤더에 포함하여 API 호출|

### 2-2. Auth Layer (v2.0 신규)

|컴포넌트|역할|
|---|---|
|`api/auth.py`|소셜 로그인(구글/카카오 OAuth 2.0), 자체 가입(이메일+비밀번호 bcrypt), 로그인, 토큰 갱신, 로그아웃 처리|
|`core/token_manager.py`|JWT Access Token(30분) 발급·검증, Refresh Token(14일) 발급·Rotation, 블랙리스트 관리(Redis)|

### 2-3. API Layer

|컴포넌트|역할|
|---|---|
|`app.py`|요청 라우팅, JWT 미들웨어(인증 검증), 페이지네이션 공통 처리, 온보딩(F-07), 공유 카드 생성(F-09) 총괄|

### 2-4. Service Layer

|컴포넌트|담당 기능|
|---|---|
|`services/profiler.py`|F-04 개인화 프로파일링 & 메모리 관리, 독서대(등록·완독·삭제·XP 회수), 리뷰 처리, 콜드스타트 전환|
|`services/gacha.py`|F-02 운명의 책 뽑기(Redis 6h 캐시 우선 조회), F-09 뽑기 카드 생성|
|`services/social.py`|F-08 유저 유사도 매칭(Qdrant Top-K), 친구 요청 처리|
|`services/xp_engine.py`|F-06 XP 적립·차감(SELECT FOR UPDATE), 일일 한도 체크, 진화 이벤트 트리거, 부화(첫 책 등록) 처리|

### 2-5. Core Layer

|컴포넌트|담당 기능|
|---|---|
|`core/vector_db.py`|Qdrant 연결, 도서/유저 벡터 검색 및 색인|
|`core/llm_client.py`|HCX API 호출, 고정 페르소나 System Prompt 관리, 쿼리 정제|
|`core/reranker.py`|Top-10 후보를 LLM으로 재점수화 → 최종 Top-3 선정. S_personal(벡터50%+장르30%+이력20%) / S_pop(Log정규화) / S_recency(지수감쇠) 산출|

### 2-6. Data Layer

|컴포넌트|용도|비고|
|---|---|---|
|PostgreSQL|모든 영구 데이터 (users, reading_shelf, reviews, xp_transactions, refresh_tokens 등 17개 테이블)|XP 동시성: SELECT FOR UPDATE|
|Qdrant|book_vectors(추천 검색), user_vectors(소셜 매칭)|로컬 → Qdrant Cloud 전환 가능|
|Redis|gacha_candidates(6h TTL), token_blacklist(Access TTL), session messages|캐시 장애 시 Qdrant 직접 조회 Fallback|

### 2-7. External APIs

|외부 서비스|호출 주체|용도|
|---|---|---|
|Google / Kakao OAuth|`auth.py`|소셜 로그인 인증|
|HyperCLOVA X|`llm_client.py`, `reranker.py`|쿼리 정제, 응답 생성, 리랭킹, 명대사 추출|
|CLOVA Embedding|도서 적재 배치|도서 메타데이터 벡터화 → Qdrant 색인|
|도서관정보나루 API|`library_api.py`, 도서 적재 배치|소장 여부(`/bookExist`), 도서관 검색(`/libSrch`), 인기 도서(`/loanItemSrch`)|

### 2-8. Batch Jobs

|배치명|스케줄|처리 내용|
|---|---|---|
|소셜 매칭 배치|Daily 03:00 KST|유저 프로파일 벡터 갱신 → Qdrant upsert → 유저별 Top-3 유사 유저 검색(O(N×K)) → 매칭 결과 PostgreSQL 저장|
|뽑기 캐시 워밍|Every 6h (00:00/06:00/12:00/18:00)|활성 유저 대상 개인화 Top-50 후보 벡터 검색 → Redis 캐싱 (On-demand 캐싱도 병행)|
|도서 데이터 적재|Weekly 월 04:00 KST|도서관정보나루 loanItemSrch → books 테이블 upsert → CLOVA Embedding → Qdrant book_vectors upsert|

## 3. 주요 요청 흐름

### 3-1. F-00: 인증 플로우 (소셜 로그인)

```mermaid
sequenceDiagram
    actor User
    participant App as Client App
    participant Auth as auth.py
    participant OAuth as OAuth Provider<br/>(Google/Kakao)
    participant TM as token_manager.py
    participant PG as PostgreSQL
    participant Redis

    User->>App: 소셜 로그인 버튼 클릭
    App->>OAuth: Authorization Code 요청 (리다이렉트)
    OAuth-->>App: Authorization Code 반환
    App->>Auth: POST /auth/social (code + provider)
    Auth->>OAuth: Code → Token 교환
    OAuth-->>Auth: Access Token + 사용자 정보 (email, name)
    Auth->>PG: email로 유저 조회
    alt 기존 유저
        PG-->>Auth: 유저 정보 반환
    else 신규 유저
        Auth->>PG: users INSERT (auth_provider, email)
        PG-->>Auth: 신규 user_id
    end
    Auth->>TM: JWT 발급 요청
    TM->>TM: Access Token (30m) + Refresh Token (14d) 생성
    TM->>PG: refresh_tokens INSERT (token_hash, expires_at)
    TM-->>Auth: Access + Refresh Token
    Auth-->>App: JWT + 신규 유저 여부
    alt 신규 유저
        App->>User: 온보딩 플로우 (F-07) 진입
    else 기존 유저
        App->>User: 메인 화면
    end
```

### 3-2. F-00: 토큰 갱신 플로우

```mermaid
sequenceDiagram
    actor User
    participant App as Client App
    participant MW as JWT 미들웨어
    participant TM as token_manager.py
    participant PG as PostgreSQL
    participant Redis

    User->>App: API 호출 (만료된 Access Token)
    App->>MW: Authorization: Bearer {expired_token}
    MW->>Redis: 블랙리스트 확인
    Redis-->>MW: 미등록
    MW->>MW: Access Token 만료 확인
    MW-->>App: 401 Unauthorized
    App->>TM: POST /auth/refresh (Refresh Token via HttpOnly Cookie)
    TM->>PG: refresh_tokens에서 token_hash 조회
    alt 유효한 Refresh Token
        TM->>TM: 새 Access Token (30m) 생성
        TM->>TM: 새 Refresh Token (14d) 생성 (Rotation)
        TM->>PG: 기존 Refresh Token revoked_at 기록
        TM->>PG: 새 Refresh Token INSERT
        TM-->>App: 새 Access + 새 Refresh Token
        App->>User: 원래 API 재호출
    else 만료 또는 이미 사용된 Refresh Token
        TM->>PG: 해당 유저의 모든 Refresh Token 무효화 (탈취 대응)
        TM-->>App: 401 REFRESH_REVOKED
        App->>User: 재로그인 안내
    end
```

### 3-3. F-01: AI 개인화 큐레이션

```mermaid
sequenceDiagram
    actor User
    participant App as app.py
    participant MW as JWT 미들웨어
    participant Profiler as profiler.py
    participant LLM as llm_client.py
    participant VDB as vector_db.py
    participant Reranker as reranker.py
    participant LibAPI as library_api.py
    participant HCX as HyperCLOVA X
    participant Qdrant
    participant PG as PostgreSQL

    User->>App: POST /chat (질의 입력)
    App->>MW: JWT 검증
    MW-->>App: user_id 추출

    App->>Profiler: 유저 프로파일 로드
    Profiler->>PG: genre_preferences, user_principles, favorite_books 조회
    PG-->>Profiler: 프로파일 데이터

    App->>LLM: 쿼리 정제 요청
    LLM->>HCX: 핵심 키워드 · 의도 추출
    HCX-->>LLM: 정제된 쿼리

    LLM->>VDB: Top-50 벡터 검색 요청
    VDB->>Qdrant: cosine similarity search
    Qdrant-->>VDB: Top-50 후보 (score 포함)
    VDB-->>LLM: 후보 반환

    Note over Reranker: S_personal 산출<br/>0.5×S_vector + 0.3×S_genre + 0.2×S_history
    Note over Reranker: S_pop = log(loan+1)/log(max+1)<br/>S_recency = exp(-0.001×days)
    LLM->>Reranker: 동적 가중치 적용 + 메모리 부스팅(1.2x) → Top-10 추출
    Reranker->>HCX: Top-10 배치 리랭킹 호출
    HCX-->>Reranker: 점수(0~100) + 추천사유
    Reranker-->>App: Top-3 최종 선정

    App->>LibAPI: Top-3 ISBN × 등록 도서관 병렬 호출
    LibAPI-->>App: 대출 가능 여부

    App->>LLM: 고정 페르소나로 최종 응답 생성
    LLM->>HCX: 응답 생성
    HCX-->>LLM: 응답
    LLM-->>App: 최종 응답

    App->>PG: total_conversations +1
    App-->>User: 추천 카드 3개 반환
```

### 3-4. F-02: 운명의 책 뽑기

```mermaid
sequenceDiagram
    actor User
    participant App as app.py
    participant Gacha as gacha.py
    participant Redis
    participant VDB as vector_db.py
    participant Qdrant
    participant LLM as llm_client.py
    participant LibAPI as library_api.py
    participant XP as xp_engine.py
    participant PG as PostgreSQL

    User->>App: POST /gacha (뽑기 요청)
    App->>Gacha: gacha 실행

    Gacha->>PG: 오늘 뽑기 사용 여부 확인 (06:00 KST 기준)
    alt 이미 사용
        PG-->>Gacha: 사용 이력 존재
        Gacha-->>User: 429 RATE_LIMIT "오늘은 이미 뽑기를 사용했어요!"
    else 미사용
        Gacha->>Redis: gacha_candidates:{user_id} 조회
        alt 캐시 HIT
            Redis-->>Gacha: Top-50 후보 ISBN 목록
        else 캐시 MISS
            Gacha->>VDB: 개인화 Top-50 벡터 검색
            VDB->>Qdrant: cosine similarity search
            Qdrant-->>VDB: Top-50
            VDB-->>Gacha: 후보 목록
            Gacha->>Redis: 캐시 저장 (TTL 6h)
        end

        Gacha->>LibAPI: 대출 가능 도서 필터링 (실시간)
        LibAPI-->>Gacha: 대출 가능 후보

        alt 대출 가능 도서 0건
            Gacha-->>User: 404 NOT_FOUND "현재 대출 가능한 추천 도서가 없어요"
        else 후보 있음
            Gacha->>Gacha: 랜덤 1권 추출
            Gacha->>LLM: 명대사 1문장 추출 요청
            LLM-->>Gacha: 명대사
            Gacha->>Gacha: 공유 카드 생성 (1080×1080px)
            Gacha->>XP: XP 20 적립 요청
            XP->>PG: SELECT FOR UPDATE → XP 저장 + 진화 체크
            Gacha->>PG: gacha_history INSERT
            Gacha-->>User: 도서 + 명대사 + 공유 카드 + XP
        end
    end
```

### 3-5. F-04: 독서대 등록 → 완독 → 리뷰 → 삭제

```mermaid
sequenceDiagram
    actor User
    participant App as app.py
    participant Profiler as profiler.py
    participant XP as xp_engine.py
    participant PG as PostgreSQL
    participant Redis

    Note over User,PG: ── 독서대 등록 ──
    User->>App: POST /reading-shelf {isbn}
    App->>Profiler: 독서대 등록 요청
    Profiler->>PG: reading 상태 책 수 조회
    alt reading 3권 이상
        Profiler-->>User: 400 SHELF_FULL
    else 등록 가능
        Profiler->>PG: reading_shelf INSERT (status: reading, review_unlocked_at: +72h)
        Profiler->>XP: XP 100 적립 요청
        XP->>PG: SELECT FOR UPDATE → XP 적립
        alt Stage 0 & 첫 책 등록
            XP->>PG: current_stage = 1 (부화)
            XP-->>App: evolution_triggered: true
            App-->>User: 부화 애니메이션 + "드디어 태어났어!"
        else 일반 등록
            XP-->>App: evolution_triggered: false
        end
        Profiler->>Redis: gacha_candidates:{user_id} 삭제 (캐시 무효화)
        App-->>User: 등록 완료 + XP 100
    end

    Note over User,PG: ── 완독 체크 ──
    User->>App: PATCH /reading-shelf/{id}/complete
    App->>Profiler: 완독 처리
    Profiler->>PG: status → completed, completed_at 저장
    Profiler->>PG: favorite_books 업데이트, genre_preferences 재계산
    Profiler->>PG: total_books_registered +1
    Profiler->>PG: 콜드스타트 전환 체크 (등록 책 ≥ 3)
    App-->>User: 완독 완료

    Note over User,PG: ── 리뷰 작성 ──
    User->>App: POST /reviews {isbn, content, rating}
    App->>Profiler: 리뷰 조건 검증
    Profiler->>PG: reading_shelf 확인 (등록 여부 + 완독 + 72h)
    alt 조건 미충족
        Profiler-->>User: 403/412 에러 (미등록/미완독/72h 미경과)
    else 조건 충족
        Profiler->>PG: reviews INSERT (is_training_data: true)
        Profiler->>XP: XP 50 적립 요청
        XP->>PG: SELECT FOR UPDATE → XP 적립 + 진화 체크
        App-->>User: 리뷰 완료 + XP 50
    end

    Note over User,PG: ── 독서대 삭제 ──
    User->>App: DELETE /reading-shelf/{id}
    App->>Profiler: 삭제 처리
    Profiler->>PG: reading_shelf 조회 (status 확인)
    alt status == completed
```

## 6. 보안 아키텍처 (v2.0 신규)

```mermaid
flowchart LR
    subgraph CLIENT["Client"]
        AT["Access Token\n(메모리 저장)"]
        RT["Refresh Token\n(HttpOnly Secure Cookie)"]
    end

    subgraph SERVER["Server"]
        MW["JWT 미들웨어\n1. 블랙리스트 확인 (Redis)\n2. 서명 검증 (HS256)\n3. 만료 확인"]
        TM["Token Manager\n발급 · Rotation · 무효화"]
    end

    subgraph DATA["Data"]
        REDIS_BL["Redis\ntoken_blacklist:{jti}"]
        PG_RT["PostgreSQL\nrefresh_tokens"]
    end

    AT -->|"Authorization 헤더"| MW
    MW -->|"jti 조회"| REDIS_BL
    RT -->|"Cookie 자동 전송"| TM
    TM -->|"Rotation 기록"| PG_RT
    TM -->|"로그아웃 시 등록"| REDIS_BL
```

|보안 항목|구현|
|---|---|
|비밀번호 저장|bcrypt (cost=12)|
|Access Token|HS256 서명, 30분 만료, jti 포함|
|Refresh Token|14일 만료, Rotation (사용 시 새 토큰 발급 + 기존 무효화)|
|탈취 대응|이미 사용된 Refresh Token 재사용 시 → 해당 유저의 전체 세션 무효화|
|로그아웃|Access Token jti → Redis 블랙리스트 (TTL = 잔여 만료시간)|
|API Key|환경변수 또는 시크릿 매니저 (하드코딩 금지)|
|개인정보|실명·정확한 주소 수집 금지, AES-256 암호화 저장|
